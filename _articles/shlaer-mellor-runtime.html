--- title: "Shlaer-Mellor Runtime" date: 2019-08-21 description: "An explanation of runtime semantics in the Shlaer-Mellor method, including event ordering and a modeled dispatcher architecture." permalink: /shlaer-mellor-runtime/ source_url: "https://xtuml.github.io/onefactnet/shlaer-mellor-runtime/" thumbnail: "/assets/images/smarch-1024x741-4769662.png" --- Stephen Mellor and Sally Shlaer did not prescribe a pre-packaged “Shlaer-Mellor Runtime Engine” in the form of operating-system or middleware services. Instead, they defined rules governing the execution of domains modeled using the Shlaer-Mellor method. Examples include the **time and event rules**. One rule states that event ordering must be maintained between sender/receiver pairs. This requires ordering to be preserved for events exchanged between a particular sender and receiver, without necessarily requiring deterministic ordering among unrelated pairs. Another rule is **accelerated event to self**: events sent from an instance to itself are processed ahead of events sent from other instances.
